# SimplyBoost identity: verified users for the AI chat widget

**HMAC identity verification for the [SimplyBoost](https://simplyboost.io) chat widget,
for Laravel, plain PHP, Node.js and Python.** Your backend signs the logged-in user's
email; the chat widget passes the signature to SimplyBoost; the AI assistant then knows
who it is talking to, can answer account-specific questions safely, and your team sees
the customer's name instead of "Visitor #4821".

Built for customer portals, dealer portals, B2B webshops and members' areas: any site
with its own login.

| Language | Package | Install |
|---|---|---|
| PHP / Laravel | [`simplyboost/identity`](https://packagist.org/packages/simplyboost/identity) | `composer require simplyboost/identity` |
| Node.js / Express / Next.js | [`@simplyboost/identity`](https://www.npmjs.com/package/@simplyboost/identity) ([README](node/README.md)) | `npm install @simplyboost/identity` |
| Python / Django / Flask | [`simplyboost-identity`](https://pypi.org/project/simplyboost-identity/) ([README](python/README.md)) | `pip install simplyboost-identity` |

Dependency-free, MIT licensed, and every package is tested against the same
[test vectors](test-vectors.json), generated by SimplyBoost's own server code.

Full guide: **[simplyboost.io/docs/verified-visitors](https://simplyboost.io/docs/verified-visitors)**

## Laravel (12 and 13)

```bash
composer require simplyboost/identity
```

`.env` (the secret is in your SimplyBoost dashboard under **Install → Identity verification**):

```dotenv
SIMPLYBOOST_BOT_ID=your-chatbot-id
SIMPLYBOOST_IDENTITY_SECRET=your-identity-secret
```

In your layout, just before `</body>`:

```blade
<x-simplyboost-widget />
{{-- or --}}
@simplyboostWidget
```

That's it. The package is auto-discovered and:

- prints the widget for every page, signed for the logged-in user (`{email, name, ts, user_hash}`)
  and anonymous for guests;
- adds `GET /simplyboost/identity` (route name `simplyboost.identity`, `web` + `throttle:60,1`
  middleware), which returns a freshly signed identity for the logged-in user and `401` for a
  guest. The widget calls it on its own when a page has been open longer than eight minutes, so
  a portal tab left open all day still starts a verified chat;
- uses `Vite::cspNonce()` when your Content-Security-Policy sets one, or
  `<x-simplyboost-widget :nonce="$nonce" />` / `@simplyboostWidget($nonce)`.

Configuration (`php artisan vendor:publish --tag=simplyboost-config`): the auth guard, the user
attributes for email and name, the refresh route's path and middleware. When the email lives
somewhere else, decide it yourself in a service provider:

```php
use SimplyBoost\Identity\Laravel\WidgetRenderer;

WidgetRenderer::resolveUserUsing(fn ($user) => [
    'email' => $user->contact->email,
    'name'  => $user->company_name,
]);
```

## Plain PHP (7.4+)

```php
use SimplyBoost\Identity\Identity;
use SimplyBoost\Identity\Widget;

$visitor = $user
    ? Identity::visitor(getenv('SIMPLYBOOST_IDENTITY_SECRET'), $user['email'], $user['name'])
    : null;

// Just before </body>. Every value is escaped for the <script> element.
echo Widget::snippet(getenv('SIMPLYBOOST_BOT_ID'), $visitor, [
    'refresh_url' => '/simplyboost-identity.php',   // optional, see below
]);
```

The refresh endpoint is ten lines: [`php/examples/plain-php/simplyboost-identity.php`](php/examples/plain-php/simplyboost-identity.php).

| Function | Returns |
|---|---|
| `Identity::visitor($secret, $email, $name = null, $ts = null)` | `['email', 'name', 'ts', 'user_hash']`, email normalized as signed |
| `Identity::compute($secret, $email, $ts = null)` | `['ts', 'user_hash']` |
| `Identity::computeUserHash($secret, $email, $ts)` | the hex signature |
| `Identity::normalizeEmail($email)` | the email as SimplyBoost signs it |
| `Widget::snippet($botId, $visitor = null, ['refresh_url', 'nonce'])` | the widget HTML |

Invalid input (no secret, not an email address) throws `SimplyBoost\Identity\IdentityException`
(an `InvalidArgumentException`).

## How it works

```
user_hash = hex( HMAC_SHA256( secret, lowercase(trim(email)) + ":" + ts ) )
```

- `ts` is a Unix timestamp in **seconds**. SimplyBoost accepts a signature for **10 minutes**
  after `ts`, with 60 seconds of clock skew, so sign on every page render, never once.
- The email is trimmed and lowercased before signing, and the same normalized email is sent to
  the widget. The packages trim exactly what the server trims (Python's `str.strip()`), which is
  not quite what PHP's `trim()` or JavaScript's `trim()` do.
- A forged, expired or unsigned identity is ignored and the chat stays anonymous. It never fails
  open.

## Security

- **The identity secret must never reach the browser.** Read it from an environment variable or
  a secret manager on your server. Only `email`, `name`, `ts` and `user_hash` go into the page.
- If the secret leaks, rotate it in the dashboard (**Install → Identity verification**).
- Call `window.SimplyBoost.reset()` on logout in a single-page app, so the next person on a
  shared computer does not inherit the chat.
- The refresh endpoint must be on the same origin as your pages (the widget ignores any other
  origin), behind your normal session, with `Cache-Control: no-store`.

Report a vulnerability: see [SECURITY.md](SECURITY.md).

## Nederlands

**Geverifieerde gebruikers in de SimplyBoost-chatwidget.** Uw server ondertekent het e-mailadres
van de ingelogde gebruiker met een HMAC-sleutel; de widget geeft die handtekening door aan
SimplyBoost. De AI-assistent weet dan met wie hij praat, kan veilig vragen over het eigen account
beantwoorden, en uw team ziet de naam van de klant in plaats van "Bezoeker #4821". Bedoeld voor
klantportalen, dealerportalen en B2B-webshops met een eigen login.

- **Laravel:** `composer require simplyboost/identity`, zet `SIMPLYBOOST_BOT_ID` en
  `SIMPLYBOOST_IDENTITY_SECRET` in `.env` en plaats `<x-simplyboost-widget />` vlak voor `</body>`.
- **PHP, Node.js en Python:** zie de voorbeelden hierboven en in [node/](node/README.md) en
  [python/](python/README.md).
- **De sleutel komt nooit in de browser.** Bewaar hem alleen op de server (omgevingsvariabele of
  secret manager).
- Een handtekening is 10 minuten geldig; het refresh-endpoint (`/simplyboost/identity`) zorgt dat
  een tabblad dat de hele dag openstaat toch een geverifieerde chat start.
